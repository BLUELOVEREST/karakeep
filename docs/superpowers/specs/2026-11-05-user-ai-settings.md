# 用户独立 AI 配置设计

## 已确认的产品边界

- 每个用户在 Web 的“设置 → AI”配置自己的模型服务，不提供“服务器默认 AI”选项。
- 用户未启用、未配置或调用失败时，不回退到全局环境变量、其他用户密钥或其他服务商。
- 首期覆盖手动总结、自动总结、自动标签和图片标签；按标签加入 List 仍使用规则引擎，不新增 AI 直接选择 List。
- 首期每个用户一个连接，可分别选择文本模型和可选视觉模型。服务类型为 OpenAI 兼容接口、Ollama。
- 语义检索及向量模型配置不纳入本次改造，不允许随意更改已有索引的模型或维度。
- 先 Web 配置，APK 继续消费服务端结果；本期不增加 APK 配置页面。模型配置、API 和后台任务必须使用同一套用户级解析逻辑。

## 页面与交互

保留现有 AI 页面及语言、标签风格、候选标签和提示词设置，新增连接与模型区域。

1. 选择服务类型，填写 Base URL 和 API Key。OpenAI 兼容接口要求 Key；Ollama 的 Key 可选。Base URL 接受该服务公开说明的完整前缀，不自动猜测或重复添加 `/v1`。
2. 点击“获取模型列表”，服务端使用当前草稿配置请求模型列表，而不是要求先保存密钥。
3. OpenAI 兼容接口使用其 `/models` 能力；Ollama 使用原生 `/api/tags`。返回模型 ID 用于可搜索的下拉菜单，允许手动刷新。
4. 文本模型和视觉模型分别选择，视觉模型可以不配置。不能仅根据模型名称或出现在列表中就宣称支持图片。
5. 保留“手动输入模型 ID”作为兼容入口：部分代理支持模型调用但不提供列表接口。获取失败不得清除已保存的模型或隐式启用 AI。
6. 点击“测试模型连接”，对选定文本模型发出小型实际推理请求，验证认证、模型调用和所选输出格式。测试只发送固定测试内容，不读取收藏；界面明确可能消耗少量模型额度。视觉模型提供单独可选测试，使用内置非用户图片。
7. 保存不自动提交历史收藏重跑。用户明确开启 AI 和自动功能后，后续任务使用个人配置；未通过测试可以保存配置，但显示未验证/测试失败，不伪装成可用。

获取模型列表只说明列表接口可访问，不等于模型一定可以推理。测试结果与对应配置版本关联；URL、Key、模型或请求参数修改后，旧测试通过状态失效。异步响应不能覆盖更新后的配置或模型列表。

### 模型排序与分组

- 不依赖上游接口返回顺序。对模型 ID 精确去重后稳定排序，保留原始 ID 作为调用参数，不改写大小写或模型别名。
- 对带明确命名空间的 ID（例如 `anthropic/claude-...`、`google/gemini-...`），按 `/` 前的命名空间归组，并按命名空间排序。命名空间只是服务商提供的分类，不宣称一定代表模型原创厂商。
- 无命名空间的模型统一放在未分组区域，按完整 ID 自然排序，让 `claude-...`、`deepseek-...`、`gpt-...` 等相同前缀尽量相邻；不使用容易误判的厂商推测表，也不把通用 `owned_by=system` 当作厂商。
- 组名和组内模型采用不区分大小写、数字感知的自然排序（英文比较规则）；比较相等时以原始 ID 再比较，保证结果稳定。排序不是性能、价格或新旧排名。
- 搜索过滤后维持原有分组与排序。刷新列表不改变用户当前选择；当前已保存模型不在返回列表时保留模型 ID，并提示它未出现在最新列表，可通过手动输入和测试继续验证。

### 视觉模型验证

- 使用程序生成的非用户测试图，随机组合颜色、几何形状或数字；提示词不透露答案。服务端核对模型返回的识别结果，不能只凭 HTTP 成功或一句自称支持图片来判定。
- 结果区分基本视觉验证通过、接口明确不支持图片、未能验证。答错、认证失败、限流、超时或解析失败不能直接归类为不支持视觉。
- 验证通过仅表示该模型通过当前接口具备基本图片理解能力，不保证复杂图片、OCR 或任意格式均可用。测试不发送收藏内容，明确提示可能消耗少量额度。
- 视觉测试结果同样绑定当前连接配置、模型和请求参数；修改后失效，不跨用户或跨服务复用。

密钥已有值时显示“已配置”和掩码，不返回原文。留空表示保留，替换需要新输入，清除为独立操作。修改服务类型或 Base URL 后，已保存密钥不得被自动发送到新地址；需重新输入 Key。Ollama 没有 Key 时无需伪造。

## 保存与执行

- 独立的用户 AI 配置记录以 `userId` 唯一归属，保存服务类型、URL、加密凭据、模型、启用状态、请求兼容参数、配置版本及修改时间。用户删除时级联清理。
- 个人总开关默认关闭。自动标签和自动总结沿用用户偏好；全局自动功能环境变量不再决定个人配置入口是否可见或个人推理是否运行。
- 首期必要兼容参数包含输出格式（structured/json/plain）；高级请求参数保持有界默认值，不能让用户无限扩大任务并发或超时。
- 手动总结先解析当前用户配置；后台任务先查询收藏所属用户，再解析其最新配置。任务载荷不携带 Key，不使用浏览器当前登录用户替代收藏所有者。
- 保存后立即对新调用生效，重启保留。已发出的请求不宣称可撤回；仍在排队的任务执行时读取最新配置。取消启用后不再发起后续用户推理。
- 调用缺少配置时标记未启用/跳过，不误报成功；401、余额或限流、模型不可用、输出格式、超时和网络问题给出脱敏说明，不自动切换服务商。
- 现有全局 AI 环境变量不复制给用户，也不作为个人配置失败的兜底。部署文档应明确旧参数与新个人配置的边界。
- 审计所有推理客户端调用点，包括可选 LLM OCR；未纳入本期的入口不能绕过个人授权读取全局推理 Key。默认本地 OCR 不受影响，本期不新增云端 OCR 功能入口。
- AI 推理状态使用现有标签/总结状态和设置页测试结果，不把模型错误混同为 resolver 抓取失败，不在本期扩展 FCM 事件范围。

## 安全与费用

- 凭据采用 AES-256-GCM 加密；使用独立、持久化的服务端加密密钥，不把该密钥存进数据库。缺少密钥时明确拒绝保存，不退化为明文。
- 部署时需要持久保存加密密钥并纳入私有备份；遗失后需重新填写个人 API Key。数据库备份不包含解密密钥。
- 普通用户只能管理自己的配置、模型列表和测试结果；管理员页面不提供查看其他用户原始密钥的入口。服务器运维仍拥有进程和密钥访问能力，不宣称端到端加密。
- 模型获取和测试均由服务端执行，限制频率、请求时长和响应大小；列表缓存按用户及连接配置版本隔离，不持久记录草稿 Key。
- 不记录 Key、Authorization、原始 SDK 异常或包含敏感信息的测试响应。前端只接收模型 ID、状态及脱敏错误。
- 自定义 URL 必须限制协议、重定向和目标地址，覆盖 DNS 重绑定及云元数据地址访问。默认阻止内网目标；本地 Ollama 等私有服务只能使用管理员明确授权的目标，不允许普通用户自行扩大范围。
- 用户启用云端 AI 前告知收藏内容可能发送到其服务商，测试和自动推理可能产生费用；服务器仅保留调度及资源上限，不提供默认模型密钥。

## 改造位置

- `packages/db`：用户配置表及迁移。
- `packages/shared`：安全的配置/状态契约，推理客户端改为显式配置，移除目标功能的隐式全局依赖。
- `packages/shared-server` / `packages/trpc`：加密存取、用户级配置解析、受控出站请求、模型获取、测试与保存接口。
- `apps/web/components/settings/AISettings.tsx`：连接设置、可搜索模型选择、测试、状态及保存交互，不隐藏现有个人设置。
- `apps/workers/workers/inference` 与手动总结路由：按收藏所有者选择配置，支持禁用和配置修改。
- 检查客户端公开配置中的全局 `isConfigured` / 自动功能开关，避免服务器未设置 Key 时阻断个人 AI。

## 验收

- 两个用户配置不同地址和 Key，手动/自动任务、模型列表及缓存严格隔离；匿名和跨用户请求拒绝。
- 未配置、关闭、重启、保存新配置、清除 Key、切换 URL、旧配置在队列中等场景不回退全局服务。
- 模型列表成功/失败/为空、手动模型 ID、认证失败、仅有列表权限、模型实际不可调用、输出格式不兼容与超时均有明确状态。
- 模型命名空间分组、大小写和数字排序、精确去重、搜索后顺序及刷新保留选择均有测试；不根据排序宣称模型新旧或性能。
- 视觉模型不依据名称推断能力；测试不读取用户收藏，列表失败不误报模型不可用。
- 视觉测试覆盖识别正确、图片输入被明确拒绝、答错/超时等未能验证场景；模型的自我声明不能替代图像识别结果。
- 缺少加密密钥、错误解密密钥、恶意 URL/重定向/DNS、超大响应与敏感异常不导致明文落库或凭据外泄。
- 默认不批量重跑旧收藏；既有 resolver 监控改动、收藏数据和向量索引不受影响。
